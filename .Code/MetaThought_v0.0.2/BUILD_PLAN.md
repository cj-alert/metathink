# MetaThought v0.0.2: first meta-queen experiment

## Authorized outcome
Build a small meta-queen generate/run/compare loop and run its first atomic prompt variation against the saved v0.0.1d baseline. Preserve baseline artifacts and application behavior. No new dependency, quota, hash, matching gate, forced round count, or automatic provider fallback.

## Repeatable process
1. Read the completed baseline request, saved configuration, attributed contributions, exchanges, assignments, and scores from its state database using a read-only connection. Never expose diagnostic logs to agents.
2. Ask Wonder for one replacement instruction in the configured chromosome position, using explicit experimental criteria and any prior operational assessment. Save the untouched reply and variant configuration.
3. Run the same confirmed baseline contract in a fresh hive with the same base settings and a single changed instruction. Use the existing runner and queen; let team formation and collapse proceed naturally.
4. Ask Wonder to compare the attributed operational evidence under the same experimental criteria, preserve uncertainty, and state the next atomic hypothesis. Save the exact assessment. This command completes one experiment; a later invocation may use its assessment as feedback.
5. Keep meta-queen records in mq_experiments and diagnostics in mq_log. Keep all source/runtime files flat within their version/run folders. Persist provider failures without silently repeating calls or replacing outputs.

## First comparison
Baseline: .Experiments/MetaThought_v0.0.1d - No quota hive, request1. Target: chromosome0 contribute. Request: original sensor contract. Unchanged base model routing, three-drone population, seed1, chromosome allocation mechanism, other prompts, and task criteria. The variant may change selected team membership through its updated signal; that is observed behavior, not a prescribed role.

## Acceptance proof
Focused tests establish isolation, exact mutation scope, no debug-log context, durable partial failures, and feedback reuse. Existing suite must pass in v0.0.2. One live variation is saved and compared with baseline using actual contributions; rejections and usage reported. A single comparison cannot establish causality, general superiority, or novelty.
